# Design decisions
- Decision: Use static ES modules and CSS with no remote runtime dependency.
  Rationale: User requested interactive pages only; direct local and static deployment work equally.
  Alternatives: React/Vite adds a build chain without changing requested behavior.
- Decision: Hash routes plus versioned localStorage and pure domain operations.
  Rationale: Deep links work on static hosting and shared persona journeys remain consistent.
  Alternatives: Backend/SSO excluded by scope; fake server is unnecessary.
- Decision: Green and warm ivory career workspace with editorial headings and restrained accents.
  Rationale: Trustworthy institutional product, approachable for first-time candidates.
- Decision: Treat market research as background, not verified claims. No employment-rate promises.
  Rationale: Original source includes estimates, correlations and unvalidated commercial assumptions.
- Decision: Stage controls represent recruiting progress, while internship signatures remain simulated.
  Rationale: A usable demonstration must not imply real legal execution.
All design uncertainties resolved from user scope; no external technical lookup required.
