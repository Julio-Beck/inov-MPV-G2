# Oportuniza Rede Constitution

## Core Principles

### I. Complete user journeys
Every primary action MUST produce a visible and persistent result across the relevant personas.

### II. Honest demonstration
The application MUST identify its demo environment and use fictitious organizations and people.
Payments, legal signatures and authentication MUST NOT be represented as real services.

### III. Accessible Portuguese interface
Pages MUST use Brazilian Portuguese, labeled controls, visible focus and responsive layouts.

### IV. Shared network, explicit institution boundaries
Opportunities MUST specify their institution audience. Student listings MUST respect that audience.
Institution dashboards MUST reflect their own students and opportunities.

### V. Verifiable simplicity
The implementation MUST prefer the smallest architecture satisfying the interactive frontend scope.
Primary journeys, persistence, validation and responsive layouts MUST be verified before delivery.

## Product Constraints
Frontend-only MVP with local persistence. No real personal data, external messaging or payments.
No unsupported employment statistics or claims of legal compliance in the interface.

## Development Workflow
Define specification, plan and tasks before implementing. Mark tasks complete only after verification.
Keep research assumptions separate from observed product behavior.

## Governance
Amend this file when scope changes. Use semantic versions; review each feature against these principles.
